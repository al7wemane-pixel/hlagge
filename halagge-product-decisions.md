# Halagge — durable decisions

- **Activation code (OTP) is demo-only by design.** User chose to show a generated code in-app for now and wire real sending (WhatsApp via Twilio, or email via SendGrid) later. The verify screen displays the code in a "demo" banner. **Why:** real sending needs an external paid account the user hasn't set up yet. **How to apply:** don't treat the missing real-send as a bug; the hook point is the verify screen + signup method toggle.
- **Admin dashboard is a SEPARATE web artifact**, not an in-app section. **Why:** pricing control + financial reports need wide tables/charts/exports and admin-only access, separate from the customer/barber mobile app. **How to apply:** build via the artifacts skill as a new web app, not inside artifacts/halagge.
- **Maps are KEYLESS (OpenStreetMap/Leaflet), NOT Google.** User has no Google Maps key, so the location picker uses free OSM: web = Leaflet iframe (carto dark tiles + Nominatim search/reverse-geocode + tap/drag pin + geolocation), native = react-native-maps UrlTile (carto dark) + expo-location reverse geocode. Reusable component `components/LocationPicker.tsx` (exports `PickedLocation {lat,lng,address}`); used in barber.tsx (home-visit toggle, HOME_FEE=30) and booking-friend.tsx (gift). **Why:** no paid API account. **How to apply:** never request `GOOGLE_MAPS_API_KEY`; LocationPicker emits coords with empty address before reverse-geocode resolves, so gate "confirm" on a non-empty `loc.address`, not just presence of `loc`.
- **Four languages everywhere:** ar / en / tr / ma (Moroccan Darija). When adding inline-conditional copy, include a distinct `ma` branch — don't fall back `ma -> ar`. Pattern in screens: `lang === "en" ? EN : lang === "tr" ? TR : lang === "ma" ? MA : AR`.
- **Admin dashboard exists** as `artifacts/admin` (react-vite, web, previewPath `/admin/`, Arabic-first RTL, dark+gold). Wired to REAL data via shared api-server + Postgres (services/settings/barbers/bookings tables, reports aggregated from bookings). Settings is a singleton row (homeFee=30, vatRate=15). Currency = SAR (ر.س). Seeded via `pnpm --filter @workspace/scripts run seed-halagge`.
- **Orval update hooks use PATCH, not PUT.** Generated `useUpdateX` calls PATCH `/x/{id}`. Server routes MUST use `router.patch(...)` or edits 404 silently (typecheck won't catch it). **Why:** contract/client/server method must match exactly. **How to apply:** when adding an update endpoint, confirm the verb in the generated client before writing the route.
- **bookings.barberId FK uses `onDelete: "set null"`** so deleting a barber who has bookings doesn't throw an FK 500; barber-earnings then shows a null-barber bucket (`غير محدد`).
- **Mobile app reads its catalog from the DB now** (admin dashboard = single source of truth). Shared hooks in `artifacts/halagge/lib/catalog.ts`: `useCatalogServices(lang)`, `useSettingsValues()` (homeFee + vatRate fraction + vatPercent), `useCatalogBarbers()`, `rankTier(rank)`. Each has fallback constants so the UI never renders empty if the API is briefly down. **Note:** fallback also triggers on a valid EMPTY list (by design — never show an empty catalog), so an intentionally-empty admin catalog still shows seed defaults on mobile. Services expose only ar/en names (DB has no tr/ma), so tr/ma service labels show Arabic.
- **Signup persists DIRECTLY to the DB — no approval gate.** On verify-success the mobile app calls `createCustomer` (customers table) or `createBarber` (barbers table) via generated hooks, then navigates. User explicitly wanted new barbers/customers to appear in admin immediately. **How to apply:** if a moderation/approval flow is ever requested, add a status column + admin action — it does not exist today.
- **Drizzle `timestamp` columns return `Date`, but generated zod response schemas expect ISO `string`.** Any route returning a row with a timestamp (e.g. customers.createdAt) must map `.createdAt.toISOString()` before `.parse()`, or it throws ZodError "Expected string, received date" (barbers table has no timestamp so it never hit this). **How to apply:** serialize timestamp fields in the route before validating the response.
- **Native API base URL must use the proxied dev domain, NOT `localhost`.** `lib/api.ts` calls `setBaseUrl("https://" + process.env.EXPO_PUBLIC_DOMAIN)` on non-web (web uses relative `/api` via the shared proxy). **Why:** on a real device `localhost` is the phone, not the API host; the workflow exports `EXPO_PUBLIC_DOMAIN=$REPLIT_DEV_DOMAIN` which routes `/api` through the shared proxy. **How to apply:** never hardcode `localhost` for native fetches here.
